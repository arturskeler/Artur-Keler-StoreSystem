# BUG-004: GET /users/ возвращает 403 обычному пользователю вместо его собственных данных

**Severity:** Medium | **Priority:** Medium | **Статус:** Open
**Версия:** Release 1 (Authorization API)
**Воспроизводимость:** стабильная

## 📌 Описание
Обычный (не суперадмин) пользователь при запросе `GET /users/` получает
`403 Forbidden`. По ТЗ (раздел 3) и по курсу обычный пользователь должен
видеть только свои данные: ID, имя, email, роль.

## 🛠 Шаги воспроизведения (Steps to Reproduce)
Предусловие: стенд запущен.
1. `POST http://localhost:8000/register/` с новыми данными обычного пользователя.
2. `POST http://localhost:8000/login/` с этими данными, сохранить `access_token`.
3. `GET http://localhost:8000/users/` с заголовком `Authorization: Bearer <access_token>`.

## ✅ Ожидаемый результат (Expected Result)
`200 OK`, в ответе только данные текущего пользователя (id, name, email, роль).
Данных других пользователей в ответе нет.

## ❌ Фактический результат (Actual Result)
`403 Forbidden`.

## 🔍 Окружение
- **Среда:** Docker / FastAPI / PostgreSQL
- **Версия:** Release 1 (Authorization API)

## Примечание
В ТЗ есть противоречие: раздел 3 разрешает обычному пользователю видеть свои
данные, раздел 5 ограничивает список суперадмином. Баг заведён по разделу 3 и
странице курса. При подтверждении трактовки «403 для обычного пользователя»
статус изменить на Rejected / Not a bug.
